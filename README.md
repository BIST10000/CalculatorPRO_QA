# Качество ПО — приложение на React

Форма ввода соответствует исходному Python-приложению: **28 начальных чисел, 7 выбранных номеров функций, 19 коэффициентов — всего 54 значения модели**. Дополнительных полей времени, точности, масштабов, границ или воздействий в форме нет.

## Запуск

Нужны современный браузер и Node.js 22.12+ с npm. Python для новой версии не требуется. Интернет нужен при первоначальной установке библиотек.

Самый простой способ: дважды нажать `START.cmd` в этой папке. При первом запуске установятся библиотеки; затем откроется браузер. Окно запуска оставьте открытым.

Либо в PowerShell:

```powershell
cd "C:\Users\lumin\OneDrive\Desktop\лр2\2021\react-app"
npm.cmd ci
npm.cmd run dev -- --port 5173 --strictPort
```

Адрес: http://127.0.0.1:5173/. Для остановки нажмите Ctrl+C. Для повторного запуска достаточно последней команды. Если папку перенесли, измените путь. Если порт занят, используйте 5174 и тот же порт в адресе. При ошибке установки библиотек не переходите к запуску, а устраните причину и повторите `npm.cmd ci`.

Для чистого сравнения используйте семь разных номеров и перезапускайте Python-приложение перед каждым опытом.

## Какие условия зафиксированы

- время от 0 до 1;
- 80 выходных точек t=i/79, i=0…79 — та же сетка, что у Python;
- шесть исходных функций воздействий без уменьшения в 10 раз;
- масштаб u* равен 1;
- точность интегрирования 1e-8;
- диапазон 0–1 используется только для предупреждения: значения за пределами диапазона не скрываются и не обрезаются.

Контрольные диаграммы дополнительно вычисляются точно при t=0; 0,25; 0,5; 0,75; 1. Они не меняют состав 80 строк основной таблицы экспорта.

## Куда смотреть

Нажмите **Рассчитать**. На вкладке **Результаты** появятся график, точная таблица пяти моментов, снимки состояния и график воздействий. Все 80 точек можно скачать кнопкой **Скачать CSV**. Снимки при t=0; 0,25; 0,5; 0,75; 1 используют отдельные шкалы по начальному и текущему состоянию, как в исходных диаграммах. Синий контур без заливки показывает начальные значения, красный — значения текущего момента. Центр соответствует подписанному минимуму шкалы, а не обязательно нулю. Подписи характеристик идут против часовой стрелки; длинные названия сокращены, полное название доступно при наведении. Все линии графиков во времени сплошные и различаются цветом. Раздел «Выбрать линии» позволяет включить нужные характеристики на графике.

**Сохранить сценарий** выгружает только 54 входных значения в JSON. **Открыть JSON** возвращает эти значения в форму. Файлы предыдущей расширенной формы не подходят: в них не было однозначного набора из семи строк. Готовые файлы нового формата находятся в `examples/compatible/`.

После изменения ввода прежние результаты помечаются как устаревшие. Перезапускать React-приложение между опытами не нужно. Ошибочные данные и численная неустойчивость показываются сообщением; расчёт можно отменить.

## Ручной тест для сравнения обеих программ

В новой версии выберите **«Сравнение · F1 = 1»**. Для Python вручную введите:

- все 28 начальных значений: **0.5**;
- номера F сверху вниз: **1, 2, 3, 4, 5, 6, 7**;
- первая строка: **0, 0, 0, 1**;
- все числовые поля остальных шести строк: **1**.

В Python обязательно откройте каждый список номеров и выберите нужный пункт, даже если он уже отображается. Затем «Вычислить» → «График» → вкладка «Графики». В React достаточно «Рассчитать».

Ожидаемая конечная сопровождаемость в **исправленном приложении: 5,048396**; анализируемость: **0,981305**. Диапазон 0–1 будет нарушен — предупреждение ожидаемо. Старые уравнения не сохраняли диапазон, и принудительного ограничения в новой версии нет.

Второй опыт: перезапустите Python-приложение, повторите тот же ввод, но последнее число первой строки замените на **0.1**. В React выберите **«Сравнение · F1 = 0,1»**. Ожидаемая конечная сопровождаемость в исправленной версии: **3,085221**; анализируемость остаётся **0,981305**.

Разница конечной сопровождаемости между этими опытами: **1,963175**. В первой строке меняется только постоянное влияние F1.

Для проверки исходных значений выберите **«Исходные значения Python»**: начальные поля совпадут с только что открытой Python-программой. Конечная сопровождаемость исправленной версии: **14,328135**. Это результат исходных коэффициентов, а не нормированная оценка качества.

Полные ожидаемые результаты: `examples/compatible/*-expected.csv` и `expected-results.json`. Допустимо отличие в последнем отображаемом знаке; исходные числа в CSV не округлены до шести знаков.

## Почему при одинаковом вводе результат может отличаться

Количество, порядок и смысл полей, воздействия и времена теперь совпадают. **Расчётные ошибки Python-приложения не возвращались.** В нём часть слагаемых обнулялась, были пропущены связи и ошибочны индексы. Исправленная версия использует восстановленные уравнения с выбранными семью функциями. Это позволяет сравнивать результат исправлений на одинаковых данных, но не обещает совпадения с ошибочной программой.

Метод интегрирования также отличается: здесь адаптивный RK4, в Python — odeint. Масштаб u* из отчёта по-прежнему трактуется как постоянный 1; его смысл в предоставленном отчёте не определён. Из самой модели нельзя вывести доказанную точность прогноза качества реального ПО.
